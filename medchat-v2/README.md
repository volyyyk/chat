# MedChat v2.0

Защищенный мессенджер для общения врачей и пациентов: клиники подтверждают врачей, пациенты подключаются по QR-коду или коду врача, история переписки зашифрована, файлы врача автоматически удаляются через 3 дня, а сообщения спустя 30 дней после приема становятся платными (в тестовом режиме списывается с тестового баланса).

## Состав проекта

| Компонент | Технологии | Назначение |
|---|---|---|
| `server/` | Node.js 22, Express, PostgreSQL, Redis, MinIO, Socket.IO | REST API, WebSocket, файлы, платежи (тестовые), бэкапы |
| `web/` | React 18 | Рабочее место врача на ПК |
| `mobile/` | React Native (Expo) | Приложения пациента и врача (Android/iOS) |
| `docs/` | Markdown | Архитектура, безопасность, законы, инструкция запуска, аудит |
| `docker/` | Docker Compose | PostgreSQL + Redis + MinIO одной командой |

## Прогресс и готовность

- **Прогресс разработки:** ориентировочно 57% по этапам roadmap (2 завершены, 4 частично реализованы, 1 отложен/необязателен). Это оценка объёма работ, не результат аудита.
- **Готовность к реальным медицинским данным:** 0% — до независимого криптографического аудита, устранения plaintext fallback, TLS, проверенных backup/restore и юридической подготовки.
- **Закрытый тест с друзьями:** возможен только на синтетических данных и с пониманием, что текущие debug-сборки не являются production-релизом.

## Быстрый старт (5 команд)

```bash
cd docker && docker compose up -d          # 1. PostgreSQL, Redis, MinIO
cd ../server
cp .env.example .env                        # 2. настройте .env
npm install                                 # 3. зависимости
npm run seed:test                           # 4. тестовые клиники/врачи/пациенты
npm run dev                                 # 5. сервер: http://localhost:3000
```

Подробная пошаговая инструкция (включая web и мобильные клиенты): [docs/GETTING_STARTED.md](docs/GETTING_STARTED.md). Для Windows/Android — [FIRST_TEST_RUN.md](docs/FIRST_TEST_RUN.md); VPS в РФ и установка Docker — [dock/TEST_HOSTING_RU.md](docs/dock/TEST_HOSTING_RU.md).

## Тестовые аккаунты (создаются `npm run seed:test`)

| Роль | Логин | Пароль | Особенность |
|---|---|---|---|
| Администратор клиники | `admin@medchat.test` | `Test1234!` | Видит чаты и баланс своей клиники |
| Врач | `doctor@medchat.test` + код клиники `TESTCLINIC` | `Test1234!` | Подтвержден клиникой |
| Пациент | `patient1@medchat.test` | `Test1234!` | Прием был 5 дней назад: сообщения бесплатные |
| Пациент | `patient2@medchat.test` | `Test1234!` | Прием был 40 дней назад: сообщения платные (тестовый баланс) |

## Ключевые возможности

- **Вход врача**: email + пароль + код клиники; аккаунт активируется только после подтверждения клиникой.
- **Пациент**: добавление чата по QR-коду или коду, чаты списком с поиском, экран информации о клинике и враче.
- **Чат**: сквозное шифрование (X25519 + XChaCha20-Poly1305), файлы с предупреждением о хранении 3 дня, голосовые сообщения, полупрозрачная плашка «удобное время для ответа».
- **Микроплатежи**: 30 дней бесплатных сообщений после приема, далее платно (80% врачу / 20% клинике). Реальные шлюзы НЕ подключены: списание идет с тестового баланса.
- **Врач**: карточки пациентов с файлами (сортировка по времени/названию), загрузка файлов, экспорт/импорт данных.
- **Облачные бэкапы**: зашифрованный паролем бэкап истории (AES, пароль знает только владелец).
- **Записи на прием и e-рецепты**: списки, отмена записи, подписание рецепта врачом.

## Тесты и CI

```bash
cd server
npm test              # unit + integration (БД мокается, сервисы не нужны)
npm run test:integration
npm run seed:test     # тестовые данные: клиника, врач, два пациента, балансы
npm run test:smoke    # e2e-смоук: сам поднимает сервер на порту 3990 и проверяет все стороны
```

GitHub Actions (`.github/workflows/ci.yml`) на каждый push в main: unit-тесты сервера и e2e-smoke (PostgreSQL + Redis) против чистой тестовой БД.

## Важное примечание

Проект носит демонстрационный характер: платежи работают на тестовом балансе, криптографические примитивы (tweetnacl) не являются сертифицированными СКЗИ. Для промышленной эксплуатации см. раздел «Дальнейшие шаги» в [GETTING_STARTED](docs/GETTING_STARTED.md) и рекомендации [аудита безопасности](docs/SECURITY_AUDIT.md).
