# Тестовый сервер MedChat в России — минимальный бюджет

Дата проверки цен: 10 ноября 2026. Цены и доступность тарифов меняются; перед оплатой перепроверьте конфигурацию в калькуляторе провайдера.

## Сначала — бесплатно

Для первого теста VPS вообще не нужен:

1. Для проверки интерфейса используйте два debug APK из [тестового релиза](https://github.com/volyyyk/chat/releases/tag/v0.0.1-alpha): ServerMock и Android client.
2. ServerMock запускается на том же телефоне; клиент подключается к `http://127.0.0.1:8080`.
3. Это только имитация API: нет настоящей БД, шифрования, файлов, платежей и многопользовательской работы.
4. Полный backend бесплатно запускается на вашем Windows-ПК через Docker Desktop. Пошаговая инструкция: [FIRST_TEST_RUN.md](../FIRST_TEST_RUN.md). Домен не нужен.

Поскольку Docker Desktop у вас пока не установлен, не начинайте с VPS. Сначала стоит закончить бесплатный локальный тест. Установка Docker Desktop нужна только для следующего уровня — настоящего backend со своей PostgreSQL, Redis и S3-совместимым хранилищем.

### Мой выбор для теста

- **Минимум расходов:** сначала локальный ПК, 0 ₽ за VPS и домен.
- **Если нужен постоянно доступный сервер для 2–5 знакомых:** смотреть Selectel VDS с 4 ГБ RAM или FirstVDS с 4 ГБ RAM; сравнить итоговую цену с IPv4, диском, резервными копиями и НДС.
- **Не брать сейчас:** Kubernetes, managed PostgreSQL, отдельный S3, балансировщики, CDN и платные панели управления. Для маленького стенда они не нужны.
- **Домен:** на первом этапе не покупать. Для временного теста можно обращаться по IP внутри закрытой сети; для публичного HTTPS-стенда позже понадобится домен и TLS. Бесплатный сертификат не делает сам домен бесплатным.

## Что обязательно даже для закрытого теста

1. Использовать только вымышленные аккаунты и синтетические сообщения. Не загружать реальные ФИО, телефоны, документы, диагнозы, анализы и медицинскую переписку.
2. Не открывать наружу PostgreSQL, Redis и S3 Console. Публичным должен быть только HTTPS reverse proxy/API.
3. Включить firewall, SSH-ключи, длинные уникальные пароли и регулярные обновления.
4. Настроить резервное копирование **и PostgreSQL, и S3-объектов**, затем проверить восстановление.
5. Не считать такой VPS production-средой и не подключать настоящих пациентов. Даже «для друзей» медицинские сведения и персональные данные могут подпадать под специальные требования закона; этот стенд не проходил аудит и юридическую проверку.

## Установка Docker Desktop на Windows — когда будете готовы

1. Откройте [официальную страницу Docker Desktop](https://www.docker.com/products/docker-desktop/) и скачайте версию для Windows.
2. Запустите установщик. Если будет выбор backend, оставьте **Use WSL 2 instead of Hyper-V**.
3. Завершите установку и перезагрузите Windows, если установщик попросит.
4. Откройте Docker Desktop из меню «Пуск» и дождитесь состояния **Engine running**.
5. Откройте PowerShell и выполните по одной команде:
   ```powershell
   wsl --update
   docker version
   docker compose version
   ```
6. Если команды `docker version` и `docker compose version` показывают версии клиента и Compose, переходите к разделу «Вариант B» в [FIRST_TEST_RUN.md](../FIRST_TEST_RUN.md).

Если Docker Desktop не запускается, не отключайте защиту Windows и не открывайте порты роутера — сначала разберём ошибку по её тексту.
