# Desktop-релиз MedChat: подписи, автоапдейт, чек-лист (Windows / Linux)

> Этап 5 ROADMAP_NATIVE.md. CI собирает установщики автоматически; подписи и
> автоапдейт требуют секретов и инфраструктуры оператора — этот гайд честно
> фиксирует границу: что делает CI, а что должен сделать оператор перед
> раздачей установщиков реальным врачам и пациентам.

## 1. Что собирает CI (сейчас)

- Джоба desktop-bundle, matrix (артефакты GitHub Actions, загружаются из
  прогона): ubuntu-latest — `.deb` + `.AppImage` (артефакт medchat-desktop-linux);
  windows-latest — NSIS `.exe` (артефакт medchat-desktop-nsis).
- Иконки генерирует build.rs (плейсхолдер #0E7490) — бинарных PNG/ICO в git нет.
- desktop-check гейтит компиляцию: команды-пробы + secure storage (keyring 3)
  типо-совместимы с medchat-core (path-деп, feature serde).

## 2. Подписи: почему их нет в CI и как включить

Сборочные подписи — секреты оператора; в репозитории их нет и быть не
должно (ROADMAP §4). Поэтому CI-артефакты НЕ подписаны — раздача «как есть»
годится только для тестов.

### Windows (NSIS .exe)

- Требуется сертификат code signing (рекомендуется EV — репутация
  SmartScreen) оператора.
- Подпись бинаря установщика (пример, при наличии сертификата):

```bash
osslsigncode sign -sha256 -t http://timestamp.digicert.com \
  -in MedChat_0.1.0_x64-setup.exe -out MedChat_0.1.0_x64-setup-signed.exe
```

- Без Authenticode-подписи Windows SmartScreen показывает предупреждение
  «неизвестный издатель» — для реальных пользователей это блокер.

### Linux (.deb / AppImage)

- Общепринятая практика: пакет распространяется через подписанный канал,
  а не подписывается сам.
- AppImage: рядом с файлом выкладывается отсоединённая GPG-подпись:

```bash
gpg --detach-sign --armor medchat_0.1.0_amd64.AppImage
```

- `.deb`: dpkg-sig либо собственный apt-репозиторий (reprepro) с GPG-ключом
  оператора — требует серверной инфраструктуры оператора.

## 3. Автоапдейт (план этапа 5, включается оператором)

Tauri updater plugin требует:

1. HTTPS-endpoint со статикой: `latest.json` (версия, дата, заметки, URL
   установщиков, подпись).
2. Пару ключей minisign (`tauri signer generate`): публичный — в конфиге
   приложения, приватный — ТОЛЬКО в GitHub Secrets релизного workflow.
3. Подписанные установщики: апдейтер не принимает неподписанные обновления.

Пока приватного ключа нет — автоапдейт не включаем: обновления вручную
скачиванием свежего установщика из Releases.

## 4. Чек-лист релиза

- CI зелёный на main; desktop-bundle собрал оба артефакта.
- Smoke на целевой ОС: кнопки «конверт x25519-box», «Double Ratchet»,
  «secure storage» возвращают ok:...
- (оператор) Authenticode-подпись .exe + timestamp; .sig для AppImage.
- Version bump: desktop/src-tauri/Cargo.toml + tauri.conf.json (синхронно).
- Release notes в GitHub Release + CHANGELOG.
- Перечитать medchat-v2/docs/LEGAL.md §2: проект не сертифицирован как
  медизделие; эксплуатация с реальными пациентами — только после
  юрдоработки оператора.

## 5. Что НЕ делаем

- Не коммитим ключи подписи и сертификаты в репозиторий — никогда.
- Не выкладываем неподписанные установщики как «промышленный» релиз для
  реальных пользователей.
- Не подключаем автоапдейт без подписанных обновлений (downgrade-риски).
