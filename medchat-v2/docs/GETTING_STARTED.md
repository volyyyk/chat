# MedChat: инструкция по запуску

Пошаговое руководство: поднять сервер, создать тестовые данные, запустить клиента врача (ПК) и клиента пациента (телефон) и проверить все основные сценарии.

> **Быстрый путь:** `medchat-v2/launcher` — запуск «по кнопке» (`node launch.js`) сам поднимает
> docker-инфраструктуру, ставит зависимости, делает seed и запускает сервер (:3000),
> web-клиника (:3002) и мобильного пациента (Expo). Папка launcher самостоятельная и удаляемая.
> Эта инструкция — для ручного запуска и понимания каждого шага.

## Предварительные требования

- **Node.js 18+** и npm
- **Docker Desktop** (или установленные вручную PostgreSQL 14+, Redis 7+, MinIO)
- Для мобильного приложения: приложение **Expo Go** на телефоне (Android/iOS)

## Шаг 1. Инфраструктура

```bash
cd medchat-v2/docker
docker compose up -d
```

Поднимутся PostgreSQL (порт 5432), Redis (6379) и MinIO (9000). Проверка: `docker compose ps` — все контейнеры Up.

> Без Docker: установите PostgreSQL/Redis/MinIO самостоятельно и пропишите их адреса в `server/.env`.

## Шаг 2. Сервер

```bash
cd medchat-v2/server
cp .env.example .env
npm install
```

Минимальный `.env` для локальной разработки:

```env
NODE_ENV=development
PORT=3000
DB_HOST=localhost
DB_PORT=5432
DB_USER=medchat
DB_PASSWORD=medchat
DB_NAME=medchat
JWT_SECRET=change-me-to-a-long-random-string
JWT_EXPIRES_IN=15m
JWT_REFRESH_EXPIRES_IN=30d
```

> Сервер не стартует с JWT_SECRET короче 8 символов (fail-fast проверка) — используйте
> длинный случайный секрет.

Создаем тестовые данные и запускаем сервер:

```bash
npm run seed:test   # создаст клинику TESTCLINIC, администратора клиники, врача и двух пациентов
npm run dev
```

Проверка: `curl http://localhost:3000/health` → `{"status":"ok",...}`

## Шаг 3. Тестовые клиенты: врач на ПК, пациент на телефоне

### Клиент врача (web, ПК)

```bash
cd medchat-v2/web
npm install
npm start        # http://localhost:3001
```

Вход:
1. Роль «Врач».
2. Email `doctor@medchat.test`, пароль `Test1234!`, код клиники `TESTCLINIC`.

### Клиент пациента (мобильный)

```bash
cd medchat-v2/mobile
npm install
npx expo start
```

Откройте в Expo Go (телефон в той же Wi-Fi сети). Вход: режим «Пациент», email `patient1@medchat.test`, пароль `Test1234!`.

## Шаг 4. Сценарии для проверки

| # | Сценарий | Как проверить | Ожидание |
|---|---|---|---|
| 1 | Чат врач↔пациент | Оба клиента открывают чат | Сообщения доставляются в реальном времени (Socket.IO) |
| 2 | Бесплатное окно | Пациент 1 пишет врачу | Сообщение уходит бесплатно (прием был 5 дней назад) |
| 3 | Платное сообщение | Пациент 2 пишет врачу | Экран оплаты: 100 ₽, сплит 80/20, списание с тестового баланса, затем сообщение отправляется |
| 4 | Голосовые | В чате кнопка микрофона | Запись → отправка → воспроизведение |
| 5 | Файлы с предупреждением | Отправка файла в чате | Перед отправкой показано предупреждение: файлы врача хранятся 3 дня |
| 6 | Карточка пациента (врач) | Врач открывает чат → информация | Файлы пациента, сортировка по времени/названию, загрузка новых |
| 7 | Записи | Вкладка «Записи» | Список приемов, отмена записи |
| 8 | e-Рецепты | Раздел «Рецепты» у врача | Создание рецепта, подписание; пациент видит подписанные |
| 9 | Облачный бэкап | Настройки → Бэкапы | Создание бэкапа с паролем, восстановление, проверка пароля |
| 10 | Неутвержденный врач | Зарегистрируйте врача и не подтверждайте | Вход блокируется: «обратитесь к руководству клиники» |

## Шаг 5. Автотесты и сквозная проверка всех сторон

```bash
cd medchat-v2/server
npm test                  # все тесты: crypto, errorHandler (с проверкой логирования), auth API
npm run test:integration  # только интеграционные
npm run seed:test         # тестовые данные (если ещё не созданы)
npm run test:smoke        # e2e-смоук: сам поднимает сервер на порту 3990
```

### Что проверяет `npm run test:smoke`

Смоук-тест логинится реальными аккаунтами и проходит потоки **каждой стороны**:

- **Клиника** (`admin@medchat.test`): чаты своей клиники, баланс клиники, статистика платежей.
- **Врач** (`doctor@medchat.test`): ответы пациентам (врач всегда пишет бесплатно), подтверждение приёма, создание и подписание e-рецепта, доход 80% (40 из 50 ₽ при сплите 80/20), real-time приём сообщений через Socket.IO.
- **Пациент 1** (`patient1@medchat.test`): бесплатные сообщения (приём был 5 дней назад), запись на приём, свои e-рецепты, облачный бэкап с паролем.
- **Пациент 2** (`patient2@medchat.test`): платные сообщения через `/api/payments/process` + отправка с `paymentTransactionId` (без двойного списания), 409 при повторном использовании транзакции.
- **Контроль доступа**: чужие чаты/приёмы/рецепты недоступны (403), Socket.IO `joinChat` в чужую комнату возвращает `forbidden`.
- **Одновременная связь**: 40 параллельных сообщений доставляются без потерь, а также индикатор печати и доставка новых сообщений в реальном времени.

CI уже настроен (`.github/workflows/ci.yml`): на каждый push в `main` гоняются unit-тесты и e2e-smoke (PostgreSQL + Redis) против чистой тестовой БД. При падении логи автоматически публикуются в `ci-logs/`.

## Устранение неполадок

- **«ECONNREFUSED 5432»** — не поднялся PostgreSQL: `docker compose up -d`, проверьте `docker compose logs postgres`.
- **«FATAL: JWT_SECRET...» при старте сервера** — задан пустой/короткий секрет: используйте строку ≥ 8 символов.
- **Сервер стартует, но rate limit падает** — Redis недоступен: rate limiter автоматически переключается на in-memory, можно работать; для полной функциональности поднимите Redis.
- **Expo Go не подключается** — телефон и компьютер должны быть в одной сети; в браузере Expo можно также открыть web-версию.
- **Порт занят** — поменяйте `PORT` в `.env` сервера и адрес API в `web/src/services/api.js` и `mobile/src/config/config.js`.

## Дальнейшие шаги (роадмап)

1. **Платежные шлюзы** — подключить ЮMoney/Tinkoff и разделение средств (сейчас тестовый баланс).
2. **Push-уведомления** — Expo Push + FCM/APNs.
3. **Идентификация пользователей мессенджера** (149-ФЗ, ст. 10.1) — через Госуслуги/операторов связи для промышленной версии.
4. **Сертифицированная криптография** — модуль ГОСТ Р 34.12-2015 (Кузнечик) / СКЗИ для УЗ-1, электронная подпись рецептов по ГОСТ Р 34.10-2012.
5. **ИИ-ассистент** — предварительная сортировка вопросов пациентов; при внедрении учитывать ГОСТ Р 59276-2020/ГОСТ Р 59277-2020 (системы ИИ).
6. **E2E-тесты** — Detox (mobile) и Playwright (web).
7. **CD** — автодеплой на VPS/K8s после зеленого CI, миграции БД в pipeline.
