# Соответствие законодательству РФ (MedChat v2.0)

> ⚠️ Документ носит технический характер и не заменяет юридическую консультацию.
> Перед запуском сервиса в эксплуатацию рекомендуется аудит юристом по ИТ и медицинскому праву.

## 2. Уровень защищенности ИСПДн

Медицинские данные относятся к специальной категории ПДн (здоровье).
При автоматизированной обработке с передачей по интернету система
классифицируется как **ИСПДн уровня защищенности УЗ-1** (или УЗ-2 при
обработке сотрудников клиники без спецкатегорий):

- межсетевое экранирование и сегментация (firewall, приватные сети Docker);
- управление доступом (JWT + refresh, роли: patient / doctor / clinic_admin / admin);
- регистрация событий безопасности (журналы Winston, requestLogger);
- защита каналов связи (TLS 1.2+ на обратном прокси, WSS для WebSocket);
- криптографическая защита при передаче и хранении (X25519 + XChaCha20-Poly1305, bcrypt);
- резервное копирование с шифрованием по паролю пользователя.

## 3. Требования 152-ФЗ: как реализовано

| Требование | Реализация |
|---|---|
| Согласие субъекта ПДн | Экран ConsentScreen: явное согласие + ФИО + дата, хранится на устройстве и передается при создании чата |
| Уведомление Роскомнадзора | Необходимо подать до начала обработки (см. docs/DEPLOYMENT.md, раздел "Регуляторные шаги") |
| Локализация баз данных | PostgreSQL размещается на серверах в РФ (требование 242-ФЗ, ст. 18) |
| Минимизация данных | Пациент идентифицируется уникальным логином, без обязательной регистрации ФИО |
| Цели обработки | Указаны в оферте и политике конфиденциальности |
| Права субъекта | Экспорт и удаление данных реализованы в API (/api/users/me, /api/backups/export) |
| Хранение не дольше необходимого | Файлы врача автоматически удаляются через 3 дня (cron fileCleanupService) |
| Обработка спецкатегорий | Только с явного согласия; сообщения шифруются end-to-end |

## 4. Врачебная тайна (323-ФЗ, ст. 13)

- Доступ врача к переписке только его собственных пациентов (проверка участника чата на сервере).
- Сервер не хранит расшифрованные тексты сообщений (E2E-шифрование).
- Файлы с видимостью doctor_only недоступны другим врачам и клинике.
- Роль clinic_admin не имеет доступа к содержимому сообщений.

## 5. Особенности для мессенджеров и медсервисов

- **Оферта (ст. 437 ГК РФ)**: docs/OFFER.md, акцепт при регистрации/согласии.
- **Правила оказания телемедицинских услуг** (Приказ Минздрава № 965н и
  323-ФЗ, ст. 36.2): чат не является телемедицинской консультацией;
  интерфейсы содержат дисклеймер; видеоконсультации требуют отдельной
  интеграции с медорганизацией.
- **Платные услуги**: микротранзакции реализованы через тестовый баланс.
  Подключение реальных платежей потребует договора с эквайрингом
  (54-ФЗ: онлайн-касса, фискальные чеки) и отражения в оферте.
- **Реклама и отзывы**: отзывы пациентов проходят модерацию (модель Review,
  флаг isApproved).

## 6. Что требуется от оператора перед запуском

1. Определить оператора ПДн (юридическое лицо) и опубликовать политику.
2. Подать уведомление об обработке ПДн в Роскомнадзор (или обосновать
   освобождение).
3. Оценить угрозы и присвоить уровень защищенности (Приказ № 996),
   аттестовать систему по УЗ-1 (Приказ ФСТЭК № 21).
4. Заключить договоры с клиниками (обработка ПДн по поручению).
5. Внедрить регламент реагирования на инциденты ИБ.
6. Хранить日志и доступа к спецкатегориям ПДн.
