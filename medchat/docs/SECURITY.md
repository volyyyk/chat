# Безопасность MedChat

## Обзор

MedChat реализует многоуровневую систему безопасности для защиты медицинских данных и персональной информации пациентов.

## Уровни защиты

### 1. Транспортный уровень (Transport Layer Security)

**Технологии:**
- WebSocket over TLS (wss://)
- SSL/TLS сертификаты
- Современные протоколы шифрования (TLS 1.2+)

**Назначение:**
- Защита от прослушивания трафика
- Защита от атак "человек посередине" (MITM)
- Аутентификация сервера

**Конфигурация:**
```javascript
// Server configuration
const https = require('https');
const fs = require('fs');

const options = {
  key: fs.readFileSync('server.key'),
  cert: fs.readFileSync('server.cert'),
  minVersion: 'TLSv1.2',
  ciphers: [
    'TLS_AES_256_GCM_SHA384',
    'TLS_CHACHA20_POLY1305_SHA256',
    'TLS_AES_128_GCM_SHA256',
    'ECDHE-ECDSA-AES256-GCM-SHA384',
    'ECDHE-RSA-AES256-GCM-SHA384'
  ].join(':')
};
```

### 2. Прикладной уровень (End-to-End Encryption)

**Алгоритмы:**
- **Обмен ключами:** X25519 (Elliptic Curve Diffie-Hellman)
- **Шифрование:** XChaCha20-Poly1305 (из libsodium)
- **Хэширование:** SHA-256
- **Подписи:** Ed25519 (опционально)

**Процесс установления ключа:**

```
1. Врач генерирует пару ключей (X25519):
   - Приватный ключ: doctorPrivateKey
   - Публичный ключ: doctorPublicKey

2. Пациент генерирует пару ключей (X25519):
   - Приватный ключ: patientPrivateKey
   - Публичный ключ: patientPublicKey

3. Обмен публичными ключами через сервер:
   - Врач -> Сервер -> Пациент: doctorPublicKey
   - Пациент -> Сервер -> Врач: patientPublicKey

4. Вычисление общего секретного ключа:
   - Врач: sharedSecret = X25519(doctorPrivateKey, patientPublicKey)
   - Пациент: sharedSecret = X25519(patientPrivateKey, doctorPublicKey)

5. Генерация ключа шифрования:
   - encryptionKey = HKDF-SHA256(sharedSecret, salt, info)
```

**Шифрование сообщений:**

```javascript
const { secretbox, randomBytes } = require('tweetnacl');

function encryptMessage(message, key) {
  const nonce = randomBytes(secretbox.nonceLength);
  const encrypted = secretbox(Buffer.from(message), nonce, key);
  return {
    ciphertext: Buffer.from(encrypted).toString('base64'),
    nonce: Buffer.from(nonce).toString('base64')
  };
}

function decryptMessage(encrypted, key) {
  const ciphertext = Buffer.from(encrypted.ciphertext, 'base64');
  const nonce = Buffer.from(encrypted.nonce, 'base64');
  const decrypted = secretbox.open(ciphertext, nonce, key);
  return Buffer.from(decrypted).toString();
}
```

### 3. Хранение данных

**Локальная база данных:**
- SQLite с шифрованием (SQLCipher)
- Шифрование ключей в ключевом хранилище устройства

**Защита ключей:**
- Приватные ключи хранятся в ключевом хранилище (Keychain на iOS, Keystore на Android)
- Ключи шифрования хранятся в зашифрованном виде
- Парольная фраза для доступа к ключам (опционально)

### 4. Аутентификация

**Механизмы:**
- Уникальные идентификаторы (UUID v4)
- Подписи сообщений (Ed25519)
- Временные токены сессий

**Процесс аутентификации:**

```
1. Врач подключается к серверу:
   - Отправляет: { type: 'auth', role: 'doctor', doctorId: UUID }
   - Сервер проверяет формат doctorId
   - Сервер создает сессию

2. Пациент подключается к серверу:
   - Отправляет: { type: 'auth', role: 'patient', doctorId: UUID, patientId: string }
   - Сервер проверяет формат doctorId
   - Сервер создает сессию

3. Обмен ключами:
   - Врач и пациент обмениваются публичными ключами
   - Устанавливается зашифрованный канал
```

## Защита от угроз

### 1. Перехват данных (MITM)

**Угроза:** Перехват и изменение сообщений в сети

**Защита:**
- TLS для защиты транспортного уровня
- End-to-end шифрование для защиты содержимого
- Подписи сообщений (опционально)

### 2. Несанкционированный доступ

**Угроза:** Доступ к данным на устройстве

**Защита:**
- Шифрование локальной базы данных
- Защита ключевого хранилища
- Аутентификация пользователя (PIN-код, биометрия)

### 3. Replay-атака

**Угроза:** Повторная отправка перехваченных сообщений

**Защита:**
- Использование nonce (уникальный для каждого сообщения)
- Временные метки (timestamp) в сообщениях
- Номера последовательности сообщений

### 4. Утечка данных через сервер

**Угроза:** Компрометация сервера и доступ к данным

**Защита:**
- Сервер не хранит персональные данные
- Сервер не имеет доступа к содержимому сообщений
- Сервер только маршрутизирует зашифрованные сообщения

### 5. Подмена личности

**Угроза:** Злоумышленник выдает себя за врача или пациента

**Защита:**
- Уникальные идентификаторы (UUID)
- Обмен публичными ключами
- Подписи сообщений (опционально)

### 6. Атака "отказ в обслуживании" (DoS)

**Угроза:** Перегрузка сервера большим количеством запросов

**Защита:**
- Ограничение количества подключений с одного IP
- Ограничение частоты сообщений
- Временное блокирование подозрительных IP

## Безопасность мобильного приложения

### Android

**Меры защиты:**
- Использование Android Keystore для хранения ключей
- Защита от reverse engineering (ProGuard, R8)
- Проверка целостности приложения
- Запрос необходимых разрешений

**Конфигурация:**
```xml
<!-- AndroidManifest.xml -->
<application
  android:allowBackup="false"
  android:fullBackupContent="false"
  android:dataExtractionRules="@xml/data_extraction_rules"
  >
</application>
```

### iOS

**Меры защиты:**
- Использование iOS Keychain для хранения ключей
- Защита от jailbreak
- App Transport Security (ATS)
- Запрос необходимых разрешений

**Конфигурация:**
```xml
<!-- Info.plist -->
<key>NSAppTransportSecurity</key>
<dict>
  <key>NSAllowsArbitraryLoads</key>
  <false/>
  <key>NSAllowsArbitraryLoadsInWebContent</key>
  <false/>
</dict>
```

## Аудит безопасности

### Логирование

**Что логируется:**
- Время подключения/отключения
- IP-адреса (анонимизированные)
- Типы сообщений (без содержимого)
- Ошибки подключения

**Что НЕ логируется:**
- Содержимое сообщений
- Персональные данные
- Ключи шифрования

### Мониторинг

- Мониторинг активных подключений
- Обнаружение аномальной активности
- Автоматическое блокирование подозрительных IP

## Рекомендации по безопасной эксплуатации

### Для врачей:

1. **Устройство:**
   - Используйте только защищенные устройства
   - Установите PIN-код или биометрию
   - Регулярно обновляйте ОС и приложение
   - Не устанавливайте приложения из непроверенных источников

2. **Сеть:**
   - Используйте только защищенные сети (Wi-Fi с WPA2/3)
   - Избегайте публичных Wi-Fi без VPN
   - Используйте мобильный интернет при отсутствии защищенной сети

3. **Данные:**
   - Регулярно резервируйте данные
   - Удаляйте данные пациентов по их запросу
   - Не передавайте доступ к устройству третьим лицам

4. **Общение:**
   - Проверяйте идентичность пациента
   - Не передавайте конфиденциальную информацию через другие каналы
   - Используйте только MedChat для общения с пациентами

### Для пациентов:

1. **Устройство:**
   - Используйте только свои устройства
   - Установите PIN-код или биометрию
   - Регулярно обновляйте ОС и приложение

2. **Сеть:**
   - Используйте только защищенные сети
   - Избегайте публичных Wi-Fi без VPN

3. **Данные:**
   - Удаляйте историю чата при необходимости
   - Не передавайте доступ к устройству третьим лицам

4. **Общение:**
   - Проверяйте QR-код или ссылку врача
   - Не передавайте свой уникальный логин третьим лицам
   - Используйте только MedChat для общения с врачом

## Процедуры в случае инцидента

### 1. Компрометация устройства врача

1. Немедленно отключите устройство от сети
2. Удалите приложение MedChat
3. Уведомьте пациентов о возможной утечке данных
4. Смените все ключи и идентификаторы
5. Установите приложение на новое устройство
6. Сообщите о инциденте в Роскомнадзор (если требуется)

### 2. Компрометация устройства пациента

1. Немедленно отключите устройство от сети
2. Удалите приложение MedChat
3. Уведомьте врача о возможной утечке данных
4. Установите приложение на новое устройство
5. Запросите у врача новую ссылку для подключения

### 3. Компрометация сервера

1. Немедленно отключите сервер
2. Проанализируйте лог файлы на предмет утечки данных
3. Поскольку сервер не хранит персональные данные, утечка маловероятна
4. Обновите SSL/TLS сертификаты
5. Запустите сервер с новыми ключами
6. Уведомьте пользователей о возможных перебоях

## Тестирование безопасности

### Автоматические тесты:

1. **Тесты шифрования:**
   - Проверка генерации ключей
   - Проверка обмена ключами
   - Проверка шифрования/расшифровки
   - Проверка целостности данных

2. **Тесты аутентификации:**
   - Проверка уникальности идентификаторов
   - Проверка обмена ключами
   - Проверка подписей сообщений

3. **Тесты устойчивости:**
   - Проверка защиты от replay-атаки
   - Проверка защиты от MITM
   - Проверка ограничения частоты сообщений

### Ручные тесты:

1. **Пенетрационное тестирование:**
   - Поиск уязвимостей в сервере
   - Поиск уязвимостей в мобильном приложении
   - Тестирование защиты от DoS

2. **Анализ кода:**
   - Статический анализ кода
   - Динамический анализ кода
   - Поиск уязвимостей в зависимостях

## Заключение

MedChat реализует комплексную систему безопасности, включающую:
- ✅ End-to-end шифрование (X25519 + XChaCha20-Poly1305)
- ✅ Защиту транспортного уровня (TLS 1.2+)
- ✅ Локальное хранение данных без центральной базы
- ✅ Защиту ключей в ключевом хранилище устройства
- ✅ Защиту от основных угроз (MITM, replay, DoS)
- ✅ Соответствие требованиям 152-ФЗ и 323-ФЗ

**Внимание:** Безопасность системы зависит не только от технических средств, но и от правильного использования приложения. Следуйте рекомендациям по безопасной эксплуатации.
