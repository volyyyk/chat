## 🔐 Реализованные механизмы безопасности

### 1. End-to-End Шифрование
- **Обмен ключами:** X25519 (Elliptic Curve Diffie-Hellman)
- **Шифрование:** XChaCha20-Poly1305 (через tweetnacl)
- **Хэширование:** SHA-256
- **Nonce:** 24 байта уникальный для каждого сообщения

### 2. Аутентификация
- Уникальные идентификаторы (UUID v4)
- Обмен публичными ключами
- Верификация через сервер-маршрутизатор

### 3. Хранение данных
- SQLite с шифрованием (SQLCipher)
- Ключи хранятся в ключевом хранилище устройства
- Локальное хранение без центральной базы

### 4. Защита от атак
- Rate limiting (ограничение частоты сообщений)
- Защита от replay-атаки (nonce)
- TLS/SSL для транспортного уровня
- Валидация всех входящих сообщений

## 🏥 Соответствие 152-ФЗ

### Реализованные требования:

1. **Минимизация персональных данных**
   - Обрабатываются только уникальные идентификаторы
   - Нет сбора ФИО, адресов, телефонов и т.д.

2. **Локальное хранение**
   - Вся история чатов хранится на устройствах
   - Нет центральной базы данных

3. **Согласие на обработку**
   - Явное согласие пациента при подключении
   - Согласие врача при первом запуске

4. **Конфиденциальность**
   - End-to-end шифрование
   - Доступ только врачу и пациенту

5. **Врачебная тайна (ст. 13 323-ФЗ)**
   - Защита медицинской информации
   - Нет доступа третьим лицам

6. **Уровень защищенности УЗ-2**
   - Организационные меры
   - Технические меры
   - Контроль целостности

### Протокол обмена

```
1. Врач генерирует QR-код с doctorId
2. Пациент сканирует QR-код
3. Пациент вводит уникальный логин
4. Устанавливается WebSocket соединение
5. Обмен публичными ключами
6. Установление общего секретного ключа
7. End-to-end шифрование сообщений
```

## 🚀 Как запустить

### Сервер

```bash
cd server
npm install
npm start
```

Сервер будет доступен на `ws://localhost:3000`

### Мобильное приложение

```bash
cd mobile
npm install
npx react-native run-android  # или run-ios
```
