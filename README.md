# 🏥 MedChat — телемедицинская платформа «клиника — врачи — пациенты»

![CI](https://github.com/volyyyk/chat/actions/workflows/ci.yml/badge.svg?branch=main)
![License](https://img.shields.io/badge/license-MIT-blue.svg)
![Stack](https://img.shields.io/badge/stack-Node%20%2B%20React%20Native%20%2B%20React-64c8c8.svg)
![E2E](https://img.shields.io/badge/E2E-X25519%20%2B%20NaCl%20box-green.svg)

**MedChat v2** — функциональный прототип телемедицинской платформы для тестирования сценариев «клиника — врач — пациент»: чаты, записи, рецепты, файлы, тестовый баланс, E2E-конверты и нативные клиенты. CI проверяет сборку и тесты, но проект **не готов к работе с реальными пациентами**: нет независимого криптографического/пентест-аудита, production-подписей приложений, завершённой юридической и эксплуатационной подготовки.

---

## 🔑 Ключевые фишки

- **Сквозное E2E-шифрование переписки (X25519 + NaCl box)**: текст сообщения
  шифруется **на устройстве отправителя**; сервер получает и хранит только
  шифротекст — plaintext в БД физически отсутствует. Приватный ключ никогда
  не покидает устройство; администраторы (clinic_admin/system_admin) **не могут
  читать переписку** — они не участники E2E-разговора. Если у какого-то участника
  ещё нет ключа, клиент автоматически отправляет plaintext (graceful fallback) —
  чат никогда не ломается. Реестр публичных ключей: модель UserKey + API
  (`POST /api/keys`, `GET /api/chats/:id/keys`), ротация и деактивация ключей.
- **Платные сообщения с честной экономикой**: первое сообщение бесплатно, окно
  30 дней после приёма бесплатно, далее — списание с тестового баланса (50 ₽) в
  SQL-транзакции с row-locks (`SELECT ... FOR UPDATE`) — двойного списания и
  отрицательного баланса не бывает физически. Сплит дохода **врачу 80 % / клинике 20 %**
  с override на клинику.
- **Real-time чаты (Socket.IO) с проверкой членства**: `joinChat` в чужую комнату
  возвращает `forbidden` — сервер сам джойнит комнаты только после проверки
  `canAccessChat` по БД. 40 параллельных сообщений без потерь (в smoke-тесте).
  E2E-конверты приходят и через сокет: клиент расшифровывает локально.
- **Голосовые сообщения и файлы**: запись m4a на Expo-av, загрузка в MinIO (S3),
  MIME-фильтр, файлы врача автоудаляются через 3 дня.
- **Электронные рецепты**: врач создаёт, «подписывает» (`POST /:id/sign`), пациент
  видит только подписанные; печатная форма HTML со специальностями врача.
- **Записи на приём**: подтверждение врачом, отмена, статусы, окно бесплатных
  сообщений привязано к completed-приёму.
- **4 роли с RBAC**: `system_admin / clinic_admin / doctor / patient`;
  ownership-проверки на каждом эндпоинте (чужие чаты/транзакции/рецепты → 403,
  покрыто IDOR-тестами).
- **Базовые меры безопасности и автотесты**: bcrypt-12, JWT HS256 с пиннингом алгоритма,
  ротация + revoke refresh-токенов, Joi stripUnknown на всех роутах, rate-limit
  (Redis с fallback), fail-fast на слабый JWT_SECRET, privateKey не покидает
  сервер, цены только серверные (клиентские суммы игнорируются), серверная
  валидация E2E-конвертов (лимиты размеров, пустой content, бокс отправителя).
- **Запуск «по кнопке»**: `launcher` поднимает docker-инфраструктуру, сид, сервер,
  web-клинику и Expo-пациента одной командой (`node launch.js`).
- **CI с e2e на каждый пуш**: unit + integration + security без БД, плюс
  e2e-smoke по основным ролям против Postgres+Redis; диагностические логи
  загружаются как краткоживущие GitHub Actions Artifacts (не коммитятся в main).
- **Честная карта проекта для ИИ и людей**: `docs/readme_for_AI.md` — все контракты,
  socket-протокол, платёжная логика, E2E-контракт и **все заплатки и компромиссы**
  задокументированы.

## 💪 Преимущества

- **Конфиденциальность по построению**: содержимое сообщений недоступно даже
  оператору сервера (E2E, шифротекст-only в БД); модель доверия и остаточные
  ограничения честно зафиксированы в LEGAL.md §2.
- **Прозрачность**: ни одного «магического» блока — платёжная логика, права доступа
  и криптодокументированы; мёртвый/сломанный код не копится, а вычищается
  (старое мёртвое «E2E» удалено, настоящее E2E спроектировано заново: X25519
  key exchange + серверный реестр публичных ключей).
- **Устойчивость к регрессиям**: зелёный CI обязателен, smoke покрывает все роли
  и негативные сценарии (403/409/402), security-наборы проверяют JWT, регистрацию,
  платежи и IDOR.
- **Документы для юридической проработки**: LEGAL / PRIVACY_POLICY / OFFER — черновая
  техническая база, не юридическое заключение и не подтверждение соответствия 152-ФЗ,
  323-ФЗ, 149-ФЗ или требованиям ФСТЭК. Перед эксплуатацией нужна проверка специалистами.
- **Понятный путь роста**: стратегия перехода к нативным клиентам (iOS/Android/
  Windows/Linux) и вынесения горячих блоков на Rust —
  [`medchat-v2/docs/ROADMAP_NATIVE.md`](medchat-v2/docs/ROADMAP_NATIVE.md).
- **Минимальный порог входа**: тестовые аккаунты, seed-команда, docker-compose,
  лаунчер, пошаговый GETTING_STARTED.

## 🚀 Быстрый старт

Для первого запуска на Windows/Android используй пошаговую инструкцию
[medchat-v2/docs/FIRST_TEST_RUN.md](medchat-v2/docs/FIRST_TEST_RUN.md): там есть быстрый тест
на двух APK и полноценный локальный backend через Docker Desktop.

```bash
# Вариант 1 — запуск «по кнопке»:
cd medchat-v2/launcher && node launch.js     # меню: clinic / doctor / patient / all

# Вариант 2 — вручную:
cd medchat-v2/server
cp .env.example .env && npm install
npm run seed:test     # тестовые данные
npm run dev           # API на :3000
```

Тестовые аккаунты (пароль у всех `Test1234!`): `admin@medchat.test` (clinic_admin),
`doctor@medchat.test` (врач), `patient1@medchat.test` (200 ₽), `patient2@medchat.test` (1000 ₽).

Тесты: `npm test` (unit+integration+security, БД мокается), `npm run test:smoke` (e2e по всем ролям).

## 📊 Реальный статус

- **Backend:** API, тестовый баланс, чаты, записи, рецепты, файлы и тестовые сценарии реализованы; реальные платёжные шлюзы и SMS не подключены.
- **E2E:** X25519/NaCl-конверты и Double Ratchet интегрированы в нативные клиенты; при отсутствии ключей есть plaintext-fallback. Протокол требует независимого криптографического аудита.
- **Android:** есть unsigned debug APK; подпись и Play Console не настроены.
- **iOS:** Swift/UniFFI smoke и xcframework собираются в CI; TestFlight/подписанного IPA пока нет.
- **Desktop:** Tauri-установщики собираются в CI, но не подписаны; автообновление не настроено.
- **Инфраструктура:** локальный Compose — тестовый контур; публичного production-хостинга, домена, TLS и расписания резервного копирования ещё нет.
- **Эксплуатация:** только синтетические данные. Не использовать для диагностики, лечения или хранения медицинских данных.

CI зелёный означает, что автоматические проверки прошли на конкретном commit, а не что продукт готов к промышленному использованию.

## 🧭 Дорожная карта: нативные платформы и системные языки

Кратко (полный план — [`medchat-v2/docs/ROADMAP_NATIVE.md`](medchat-v2/docs/ROADMAP_NATIVE.md)):

1. **Общее ядро** — контрактные API-сценарии выполнены; RN-клиент оставлен reference, общая криптография и ratchet вынесены в Rust.
2. **Rust-ядро** (`libmedchat_core`): AES-GCM, хэши, Double Ratchet (прототип +
   персистентность save/restore, bincode); UniFFI-биндинги для Swift/Kotlin,
   napi-rs для Node — готовы (гайд подключения — `docs/INTEGRATION_BINDINGS.md`).
3. **iOS (Swift/SwiftUI)** и **Android (Kotlin/Jetpack Compose)** — каркасы, сервисы и CI smoke готовы; Android debug APK собирается, production-подписи/TestFlight/Play Console — операторские задачи.
4. **Desktop**: Tauri 2 (Rust) — Windows `.exe` и Ubuntu `.deb`/AppImage из одной кодовой базы (каркас готов, установщики `.deb`/AppImage/`.exe` собираются в CI; секреты Double Ratchet — в Credential Manager/libsecret; подписи, автоапдейт и чек-лист релиза — гайд medchat-v2/docs/DESKTOP_RELEASE.md). E2E-конверты x25519-box (этап 7) — рабочий клиентский путь: ключ устройства в secure storage (medchat.e2e), шифрование/расшифровка в Rust-ядре, wire-формат байт-в-байт совместим с мобильным клиентом; при неполном покрытии ключами — честный plaintext-fallback.
5. **Серверные горячие пути** на Rust (napi-rs) — начато (этап 6): SHA-256 checksum в medchat-core + napi + серверная обёртка с fallback на node:crypto; чексуммы целостности бэкапов и gzip-сжатие бэкапов (до шифрования, flate2 + честный fallback) подключены, k6-нагрузочный в CI (фиксированный профиль, p95 гейтится); при росте — отдельный websocket-gateway.
6. **E2E-шифрование**: X25519 + NaCl box для сообщений/файлов/голосовых и Double Ratchet
   интегрированы в нативные клиенты; текущая инициализация использует X3DH-lite без prekeys.
   Нужны независимый аудит, проверка гарантий forward secrecy и устранение автоматического
   plaintext-fallback до реального использования.
7. C#/.NET и Java — точечно (WinAPI-интеграции, JVM-интеграции), а не по умолчанию.

## 🔒 Безопасность и право

В репозитории есть внутренний security review и автоматические проверки: саморегистрация
админов запрещена, цены фиксируются сервером, JWT с пиннингом, IDOR покрыты тестами.
Независимый внешний пентест/криптографический аудит НЕ проводился. Сквозное E2E-шифрование
содержимого сообщений включено: сервер хранит только шифротекст (контракт —
`docs/readme_for_AI.md`, раздел «E2E-контракт»); остаточные ограничения честно
перечислены в LEGAL.md §2. Реальные платёжные шлюзы отключены (только тестовый
баланс) — осознанное решение владельца. Проект **не является** сертифицированным
медизделием и не аттестован ФСТЭК; эксплуатация с реальными пациентами требует
юридической доработки оператора (см. `medchat-v2/docs/LEGAL.md`). Лицензия — **MIT**
(без гарантий).
