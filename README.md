# 🏥 MedChat — телемедицинская платформа «клиника — врачи — пациенты»

![CI](https://github.com/volyyyk/chat/actions/workflows/ci.yml/badge.svg?branch=main)
![License](https://img.shields.io/badge/license-MIT-blue.svg)
![Stack](https://img.shields.io/badge/stack-Node%20%2B%20React%20Native%20%2B%20React-64c8c8.svg)

**MedChat v2** — готовая к развитию платформа для платных чатов пациент ↔ врач:
real-time переписка с голосовыми и файлами, электронные рецепты с подписью,
записи на приём, честная внутренняя экономика и безопасность, проверенная
аудитом и автотестами на каждый коммит.

---

## 🔑 Ключевые фишки

- **Платные сообщения с честной экономикой**: первое сообщение бесплатно, окно
  30 дней после приёма бесплатно, далее — списание с тестового баланса (50 ₽) в
  SQL-транзакции с row-locks (`SELECT ... FOR UPDATE`) — двойного списания и
  отрицательного баланса не бывает физически. Сплит дохода **врачу 80 % / клинике 20 %**
  с override на клинику.
- **Real-time чаты (Socket.IO) с проверкой членства**: `joinChat` в чужую комнату
  возвращает `forbidden` — сервер сам джойнит комнаты только после проверки
  `canAccessChat` по БД. 40 параллельных сообщений без потерь (в smoke-тесте).
- **Голосовые сообщения и файлы**: запись m4a на Expo-av, загрузка в MinIO (S3),
  MIME-фильтр, файлы врача автоудаляются через 3 дня.
- **Электронные рецепты**: врач создаёт, «подписывает» (`POST /:id/sign`), пациент
  видит только подписанные; печатная форма HTML со специальностями врача.
- **Записи на приём**: подтверждение врачом, отмена, статусы, окно бесплатных
  сообщений привязано к completed-приёму.
- **4 роли с RBAC**: `system_admin / clinic_admin / doctor / patient`;
  ownership-проверки на каждом эндпоинте (чужие чаты/транзакции/рецепты → 403,
  покрыто IDOR-тестами).
- **Безопасность по-взрослому**: bcrypt-12, JWT HS256 с пиннингом алгоритма,
  ротация + revoke refresh-токенов, Joi stripUnknown на всех роутах, rate-limit
  (Redis с fallback), fail-fast на слабый JWT_SECRET, privateKey не покидает
  сервер, цены только серверные (клиентские суммы игнорируются).
- **Запуск «по кнопке»**: `launcher` поднимает docker-инфраструктуру, сид, сервер,
  web-клиника и Expo-пациента одной командой (`node launch.js`).
- **CI с e2e на каждый пуш**: unit + integration + security без БД, плюс
  e2e-smoke 50 проверок по всем ролям против Postgres+Redis; при падении логи
  автоматически публикуются в `ci-logs/`.
- **Честная карта проекта для ИИ и людей**: `docs/readme_for_AI.md` — все контракты,
  socket-протокол, платёжная логика и **все заплатки и компромиссы** задокументированы.

## 💪 Преимущества

- **Прозрачность**: ни одного «магического» блока — платёжная логика, права доступа
  и криптодокументированы; мёртвый/сломанный код не копится, а вычищается
  (мёртвое E2E-«шифрование» честно удалено, а не притворяется рабочим).
- **Устойчивость к регрессиям**: зелёный CI обязателен, smoke покрывает все роли
  и негативные сценарии (403/409/402), security-наборы проверяют JWT, регистрацию,
  платежи и IDOR.
- **Готовность к юристам**: LEGAL / PRIVACY_POLICY / OFFER под законодательство РФ
  (152-ФЗ, 323-ФЗ, 149-ФЗ, ФСТЭК УЗ-1), явные дисклеймеры и защита разработчиков (MIT).
- **Понятный путь роста**: стратегия перехода к нативным клиентам (iOS/Android/
  Windows/Linux) и вынесения горячих блоков на Rust —
  [`medchat-v2/docs/ROADMAP_NATIVE.md`](medchat-v2/docs/ROADMAP_NATIVE.md).
- **Минимальный порог входа**: тестовые аккаунты, seed-команда, docker-compose,
  лаунчер, пошаговый GETTING_STARTED.

## 🚀 Быстрый старт

```bash
# Вариант 1 — запуск «по кнопке»:
cd medchat-v2/launcher && node launch.js     # меню: clinic / doctor / patient / all

# Вариант 2 — вручную:
cd medchat-v2/server
cp .env.example .env && npm install
npm run seed:test     # тестовые данные
npm run dev           # API на :3000
```

Тестовые аккаунты (пароль у всех `Test1234!`): `admin@medchat.test` (clinic_admin),
`doctor@medchat.test` (врач), `patient1@medchat.test` (200 ₽), `patient2@medchat.test` (1000 ₽).

Тесты: `npm test` (unit+integration+security, БД мокается), `npm run test:smoke` (e2e по всем ролям).

## 🧭 Дорожная карта: нативные платформы и системные языки

Кратко (полный план — [`medchat-v2/docs/ROADMAP_NATIVE.md`](medchat-v2/docs/ROADMAP_NATIVE.md)):

1. **Общее ядро** — выделение протокола/крипто/синхронизации из UI-клиентов.
2. **Rust-ядро** (`libmedchat_core`): AES-GCM, хэши, будущий Double Ratchet;
   UniFFI-биндинги для Swift/Kotlin, napi-rs для Node.
3. **iOS (Swift/SwiftUI)** и **Android (Kotlin/Jetpack Compose)** поверх общего ядра.
4. **Desktop**: Tauri 2 (Rust) — Windows `.exe` и Ubuntu `.deb`/AppImage из одной кодовой базы.
5. **Серверные горячие пути** на Rust (napi-rs), при росте — отдельный websocket-gateway.
6. **E2E-шифрование** (Double Ratchet на Rust-ядре) + при необходимости ГОСТ СКЗИ.
7. C#/.NET и Java — точечно (WinAPI-интеграции, JVM-интеграции), а не по умолчанию.

## 🔒 Безопасность и право

Проведён security-аудит с попытками взлома: саморегистрация админов запрещена,
цены фиксируются сервером, JWT с пиннингом, IDOR закрыты. Реальные платёжные
шлюзы отключены (только тестовый баланс) — осознанное решение владельца.
Проект **не является** сертифицированным медизделием и не аттестован ФСТЭК;
эксплуатация с реальными пациентами требует юридической доработки оператора
(см. `medchat-v2/docs/LEGAL.md`). Лицензия — **MIT** (без гарантий).
